## CSV 구조와 범례 판정

- 숫자형 -1.csv: 아이디/위도/경도/고도. 이동 좌표이며 시설 존재 근거가 아님. -2.csv: 앞 열에 장소명·장소설명·이미지파일(명)이 추가된 조사 지점.
- 2020 한글형: 장소명칭/장소상세정보/무장애관광정보/추천코스여부/데이터기준일자. 빛의벙커형: ID/lat/lon/Title/Description/Image/Point/info/A/B/etc. 기존2021 양식은 그대로 처리.
- **etc 범례 정의만 있고 어떤 지점 info에도 코드가 지정되지 않으면 미확인.** CSV 전체 범례에 시설 명칭이 존재하는 것만으로 설치를 추정하지 않는다.
- info 코드가 해당 etc 범례와 연결되고 실제 위경도 지점이 있으면 원문이 명시한 시설 지점으로 있음(검토필요) 처리. 원문이 직접 명시한 시설 지점 분류이며 독립적인 현장 검증/안전 확인은 아님. info 코드·지점 행·범례 행·원문을 함께 보존. 단차/계단/경사/명시 부정 등 제약은 기존 조건부/없음 규칙 적용.
- 코드 연결만 있고 좌표도 없으며 시설명/설명이 별도로 없으면 미확인. 의미 없는 숫자 코드도 미확인. 범례는 실제 지점의 설명으로 합성되지 않으면 장소 시설로 사용하지 않음.

## 재귀 읽기 변경

- src/raw_scan.py: 하위 폴더를 재귀 순회, images는 개수만 기록하고 파싱 제외, 공통 가이드/zip 제외 사유 기록. DB source_file.file_name은 data/raw 기준 상대경로로 저장하므로 같은 파일명을 구분할 수 있음.
- 장소명이 없는 파일은 실제 장소 폴더명으로 연결하고 place_name_source='folder'. 2019/2020 같은 분류 폴더나 images를 장소명으로 사용하지 않음. 현재 평면2019 파일은 기존 ID 가이드 기반 manifest_override 연결을 유지한다.
- 같은 내용이라도 서로 다른 장소 폴더의 파일은 섞거나 삭제하지 않는다. 동일 장소·동일 SHA의 중복 사본만 제외하고 원본/선택 경로를 기록한다. 기존 최상위2021 파일의 ID·연결 규칙과 관광공사 통합 유지.
- 18개 모의 장소 폴더에 같은 파일명·같은 CSV바이트·같은 가이드·이미지1개를 각각 넣은 독립 빌드로18개 출처 분리/folder 연결/가이드 제외 검증. 이는 모의 검증이며 실제18폴더를 발견했다는 뜻이 아님.
- 반복 HWP 읽기 후 Windows 파일 잠금이 남지 않도록 olefile 핸들을 finally에서 닫음. 기존2021 HWP50곳 직접 대조로 회귀 확인.

향후 시각·청각 안내 시설의 구조화된 최신 자료와 당사자 검증을 확보한 뒤 유형별 안내 범위를 확장할 계획입니다. 현재 시각·청각 이용 가능 여부나 안전을 보장하지 않습니다. 이전 절의 ‘더보기·이용자 유형 드롭다운’ 설명은 과거 화면 기록이며 현재는 제공하지 않습니다.

# 대화형 닿는제주 사용 안내 (2026-11-10)

첫 화면의 동행자·날짜 칩은 선택 사항입니다. 선택하지 않으면 질문 문장에서 읽고, 선택하면 그 값이 우선합니다. 날짜 칩에서 ‘날짜’를 선택하면 날짜·시간대를 직접 정할 수 있습니다. ‘더보기’에는 기존 이용자 유형이 있습니다.

화면 맨 아래 입력창에 질문을 쓰고 Enter 또는 초록 전송 버튼을 누릅니다. 장소 바로가기 칩도 질문을 바로 실행합니다. 개인정보를 입력하지 마세요. LLM 사용 시 질문과 공개 자료가 외부 API로 전송됩니다.

사용자 질문은 오른쪽 초록 말풍선, 답변은 왼쪽 흰 카드로 표시합니다. 답변에는 요약·추천 지도·첫 장소 카드가 나오고 ‘다음 장소 N곳 보기’로 다른 장소를 펼칩니다. ‘자세히’를 누르면 **같은 답변 안에서** 해당 장소의 코스 지도·판단·시설·주의점·복사·원문 근거가 열립니다. ‘상세 접기’로 닫습니다. 장소명 질문은 해당 장소 상세를 바로 엽니다.

카드 배지는 기존 이용 판단을 ‘가능 / 일부 주의 / 확인 필요 / 어려움’으로 짧게 표시합니다. 시설 상태값과 필수 시설 등급은 그대로이며 일반 주차·장애인 주차·장애인 화장실을 따로 읽습니다. 흐리게 표시된 ‘없음’과 ‘미확인’은 서로 다릅니다. 경사 정보 없음은 안전 확인이 아닙니다.

새 질문을 보내도 이전 질문·답변·상세는 위에 남습니다. 대화는 현재 브라우저 세션에만 보관하며 새로고침/새 세션에서 사라질 수 있습니다. ‘자료 안내’는 데이터·시스템 정보를 엽니다. 하단 접힘 칸에서도 실제 출처·Agent 과정·호출비용을 확인합니다.

# 사용자 매뉴얼 초안

작성일 2026-11-07. 설치·DB 준비는 [README](../README.md), 오류·데이터 한계는 [LIMITS](LIMITS.md)를 먼저 참고합니다. PC·폰이 같은 서버를 사용하므로 판정 규칙은 같습니다.

## 1. 시작 화면

`run_app.bat` 또는 `python launch_app.py`로 시작한 뒤 표시된 주소를 엽니다. ‘닿는제주’ 로고 아래에 ‘휠체어·유아차 여행 안내’가 표시됩니다. 이용자·날짜 칩을 고르고 하단 대화 입력창에 질문을 적습니다. 시스템 지표는 첫 화면에 펼쳐 표시하지 않습니다.

맨 아래 **데이터·시스템 정보**를 펼치면 판정 가능 장소 수, 출처별 기준일, 문장 이해 LLM/규칙 모드, 날씨 연동, 이번 달 LLM 호출 수·추정비용을 확인합니다. 비용은 참고 표시이며 월 차단은 없습니다. 키가 설정돼 있으면 문장 이해는 LLM을 기본 사용합니다.


## 2. 질문·세부 조건

‘이렇게 물어보세요’ 예시 카드를 누르면 입력·칩을 채워 바로 실행합니다. 직접 입력할 때는 ‘한림공원, 바닷가 산책로…’ 검색창에서 Enter 또는 오른쪽 파란 원형 화살표를 누릅니다.

- `한림공원 휠체어로 갈 수 있어?`: 지정 장소를 먼저 조회합니다.
- `내일 오후 수동휠체어로 화장실 있는 해안 산책로`: 시설·성격·날짜로 찾습니다.
- `이번 주 언제 바다 보러 갈까`: 조회 가능한 날짜의 강수확률을 비교합니다.

‘누구와’에서 휠체어·유아차·어르신 중 하나를 고릅니다(선택 칩을 다시 누르면 해제). 더보기에서 전동휠체어·보행약자·시각/청각장애를 고릅니다. ‘언제’는 오늘·내일·이번 주말·날짜 중 선택합니다. 이번 주말은 다가오는 토요일(일요일이면 오늘)이며 결과 칩의 실제 날짜를 확인하세요. ‘날짜’를 고른 때에만 오늘~10일 뒤 날짜 선택과 작은 시간대 입력이 나타납니다. 칩 선택은 기존 apply_form 경로로 문장보다 우선합니다. 미선택이면 문장에서 그대로 읽고, 필수 시설·지역·활동은 문장에 적습니다. 기본 시간대는 ‘문장에서 자동’입니다. 실행 중 진행 단계를 표시하고 완료 후 데이터·시스템 정보에서 세부 기록을 확인합니다.


## 3. 요약·장소명 질문

상단 칩에서 적용 조건을, 카드와 상세에서 이용 판단·주의 내용을 읽습니다. **‘휠체어 이용: 가능(일부 구간 주의)’는 원문에 이용 가능한 일부 구간 근거가 있다는 뜻**입니다. 이어지는 근거·한계도 함께 읽어야 합니다. ‘확인 필요’는 정보 부족 또는 주의 구간의 추가 확인을 요구하는 결론입니다. 원문에 없는 전체 코스 이용 불가·안전을 단정하지 않습니다.

같은 이름이 여러 건이면 데이터·시스템 정보 안의 장소명 검색 기록에서 상세/목록 건수를 확인합니다. 상세 장소 판정과 별도 목록 기록을 구분하며 미확정 연결은 자동 확정하지 않습니다. 색인만 있는 장소는 지도 위치를 표시하되 접근성 판정은 불가합니다. DB에 없는 장소는 안내 후 일반 검색합니다.

관광지 추천은 관광지 카드부터 보여 줍니다. 음식점·카페·숙박·쇼핑은 **‘근처 식사·편의 장소’**에서 별도로 읽습니다. 분류 근거가 없으면 유형 미확인으로 남깁니다. 대안 거리 km는 지정 장소 좌표로 계산한 직선거리이며 실제 보행·휠체어 경로가 아닙니다. 분류별 가까운 후보를 선정한 뒤 시설 등급·같은 등급 내 경사·거리 순으로 정렬합니다.


## 4. 등급·상태값 읽기

| 시설 조건 등급 | 의미 |
|---|---|
| 조건 충족 | 요청한 필수 시설 조건을 원본상 충족 |
| 조건부 충족 | 대체시설·도움 등 조건을 확인해야 충족 |
| 확인 필요 | 필수 시설 정보가 미확인 |
| 조건 미충족 | 필수 시설이 없다고 원문에 명시 |

필수 시설을 지정하지 않으면 ‘조건 충족’으로 표시될 수 있습니다. 이는 이용 가능·안전 판정이 아니므로 **이용 판단·경사·원문**을 확인합니다.

| 항목 상태 | 의미 |
|---|---|
| 있음 | 원문에 시설 존재 명시 |
| 없음 | 원문에 시설 부재 명시 |
| 조건부 | 원문에 제약·대체 조건 명시 |
| 미확인 | 공란·추출 한계 등으로 알 수 없음. 없음과 다름 |

추천 순위는 §5의 이용 판단·구간 수 우선 기준입니다. 장소명 질문 주변 대안은 기존 같은 등급 내 경사 순서를 유지합니다. 등급은 바꾸지 않습니다. 미측정·기준 이하 모두 안전 보장은 아닙니다. 지정 장소는 질문에 답하기 위해 맨 위에 유지합니다.

## 5. 앱 형태의 결과 화면 (2026-11-08)

추천 질문은 **질문 요약 칩 → 제주 지도(상위5곳 번호 핀) → 장소 카드** 순서입니다. 카드는 순위·장소명, 아이콘과 이용 판단, 장애인 주차·화장실·경사·어려운 구간 정보를 보여 줍니다. 가로 카드 전체를 누르면 해당 장소 상세가 열립니다. 폰은 카드를 옆으로 넘기고 PC는2~3장을 함께 봅니다. 선택 카드는 파란 테두리, 선택 핀은 크게·다른 핀은 흐리게 표시합니다. 상세 상단 ‘← 장소명’으로 목록에 돌아옵니다. ‘한림공원 휠체어로 갈 수 있어?’ 같은 장소명 질문은 추천 목록을 건너뛰고 바로 상세를 보여 줍니다.

상세는 **코스 지도 → 결론과 한 줄 이유 → 시설3칸(장애인 주차/화장실/날씨) → 주의할 곳 → 결과 복사·원문 근거 → 한계·출처** 순서입니다. 주의할 곳은5개 뒤 ‘더 보기’에서 이어 읽습니다. ‘원문 근거’ 버튼을 누르면 시설 등급·상태·인용·원본 파일/행/기준일·주소 보완 근거가 펼쳐집니다. 근처 식사·편의 장소는 상세 맨 아래 접힘 칸에서 이름·유형·거리만 확인합니다.

추천 순위는 필수 시설 없음(조건 미충족)을 전체 맨 뒤로 두고, 나머지는 빨강0→미확인→1~2→3이상 범주로 비교합니다. 같은 빨강 범주에서는 필수 시설 있음/조건부/미확인, 이용 판단, 주황 구간 수, 직선거리 순입니다. 카드에 ‘어려운 구간 N곳’을 표시하고, 필수 시설이 없으면 ‘장애인 주차 없음(필수 조건)’ 같은 빨강 문구를 표시합니다. 상태·등급과 장소명 질문의 지정 장소 우선 흐름은 바꾸지 않습니다. 미확인 구간 수는0으로 간주하지 않습니다.

지도 핀은 초록(가능/일부주의), 주황(확인 필요), 빨강(어려움)이며 번호는 카드 순위와 같습니다. 코스 선은 기존 기준대로 초록(편한 구간), 주황(경사·우회 주의), 빨강(우회 정보 없는 계단·단차)입니다. 구간 개수는 원본 파일 안의 연속 지점 사이 선 개수로, 지도에서 묶은 주의 번호 개수와 다릅니다. 같은 원문/유사도0.9 이상·30m 이내 주의 지점은 카드 번호를 합쳐 원문·출처 행을 보존합니다.

전체 Agent 작업 과정, 실제 조회 데이터, 처리 모드·소요 시간·상세 한계는 맨 아래 ‘데이터·시스템 정보’ 안에 있습니다. 상태 미확인은 시설이 없다는 뜻이 아니며 안전을 보장하지 않습니다. LLM 한도/연결 오류 시 규칙 모드로 대체합니다.

## 6. 날씨·날짜 추천

단기는 오늘~3일 뒤 시간별 예보, 중기는 4~10일 뒤 구역 단위 예보입니다. 중기 4~7일은 오전/오후, 8~10일은 하루 단위이며 풍속이 없어 강풍 판단을 하지 않습니다. 비 예보와 날짜 추천은 선택한 장소 상세에서 확인합니다.

비 예보가 있으면 오늘부터 10일 뒤까지 단기·중기예보를 자동 비교해 원래 방문일을 제외한 낮은 강수확률 날짜 1~2개를 추천합니다. 조회 실패·예보 범위 밖은 미확인으로 남기고 추천에서 제외합니다. 날짜가 없거나 이번 주/주말/언제 질문이면 기존 7일 비교를 사용합니다. 오늘 지난 시간대는 제외하며 남은 시간대가 없으면 오늘을 제외합니다. ‘날짜별 예보 비교’를 펼쳐 날짜별 확률과 정밀도를 확인합니다. 낮은 강수확률은 맑음·안전을 보장하지 않습니다.

## 7. Agent 작업 과정·한계

맨 아래 ‘데이터·시스템 정보’ 안의 Agent 작업 과정에서 단계마다 **무엇을 / 왜 / 결과 / 소요 시간**을 읽을 수 있습니다. 처리 모드·장소명 일치 건수·좌표 출처·순위 근거도 이 안에 있습니다. 비 예보 후 추가 조회는 ‘날씨 나쁨 → 다른 날짜 자동 조회’로 기록됩니다.

‘데이터 한계와 판정 규칙’에서 기준일·미확인·출처 충돌을 확인합니다. 방문 전 운영처에 실제 이용 구간·시설을 확인하세요. 응급 상황에서는 119에 연락하세요.

## 8. 기준 장소 근처 추천

‘제주 신라호텔 근처에 ６０대 어머니 모시고 산책할 만한 곳 추천해줘’, ‘중문 근처 부모님이랑 걷기 좋은 곳’처럼 기준 장소+동행자+활동을 적습니다. 전각 숫자도 정규화해 읽습니다. ‘성산일출봉 주변 유아차로 산책할 곳 내일 오후’, ‘애월 근처 비 오면 갈 만한 실내’도 같은 방식으로 입력합니다.

결과 맨 위의 **기준 위치·출처·좌표 근사**를 먼저 확인합니다. 현재 제주신라호텔·성산일출봉은 직접 좌표가 없어 소재 지역의 대표지점을 사용할 수 있습니다. 이때 ‘지정 장소 실좌표 아님’이 표시되므로 호텔 앞에서 출발하는 실제 거리로 해석하지 않습니다. 위치를 찾지 못하면 근처 지역명으로 다시 질문합니다.


어르신 보행 기준은 별도 공식 기준이 없어 경사·계단·화장실·쉼터 정보로 판단했습니다. 개인 건강 상태에 따라 다를 수 있습니다. 날짜·시간대를 정하면 기존 날씨 확인을 사용하며 비 예보에는 원문 근거가 있는 같은 지역 실내 대안을 함께 안내합니다.

‘한림공원 휠체어로 갈 수 있어?’는 기존 장소 자체 판정입니다. DB에 없는 호텔 등의 이용 가능 질문은 해당 장소의 ‘판정 데이터가 없습니다’와 근처 판정 가능 장소를 구분해 표시합니다.

## 배경지도와 표시(2026-11-09)

지도 위 ‘일반/위성’으로 전환합니다. 브이월드 키가 있으면 일반 백지도(white)가 기본이고, 위성은 위성 영상+지명입니다. 키 없음·브이월드 실패 시 기존 pydeck 기본 CARTO light 배경을 사용하고, CARTO도 실패하면 OpenStreetMap 표준 타일로 자동 전환합니다. 예비 지도에는 위성이 없어 일반으로 표시합니다. 지도 아래 실제 공급자와 출처를 확인하세요. 일시 실패 후 ‘브이월드 다시 시도’를 누를 수 있습니다.

추천 지도는 전체 장소가 들어오게 열리고 물방울 핀 번호가 카드 순위와 같습니다. 카드를 누르면 해당 코스 전체에 여백을 두어 확대하고 선택 핀은 크게, 다른 핀은 흐리게 표시합니다. 코스 선의 흰 테두리·둥근 끝은 가독성 표시이며 기존 구간 색의 의미는 같습니다. 입구·화장실·주차 아이콘은 원문 좌표가 있는 곳만 표시합니다. 입구 아이콘은 최초 조사 지점/대표 위치일 수 있어 실제 출입구 확정을 뜻하지 않습니다.
